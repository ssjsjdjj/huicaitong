# 惠才通 · 杭州人才服务研究原型

一个可在本机运行的政策知识库、证据检索与条件初筛应用，配套 SFT / GRPO 数据构造、奖励函数和可选训练入口。

独立仓库：<https://github.com/ssjsjdjj/huicaitong>。下载 ZIP 解压或克隆后，在项目根目录运行下方启动命令即可体验规则版。仓库包含合成样例、实验记录及四个小型 LoRA 适配器；基础模型、Python 环境、密钥和本机运行数据库不随仓库分发。实验结果与适配器作为冻结记录保留，`.gitignore` 会排除后续新产生的训练输出和本机配置。

**当前为 v0.4：修复八项使用体验问题，增加具体冲突说明、复核进度恢复、金额与渠道摘要、材料页内重算及可打印中文报告。** 使用及验收记录见 `docs/UX_FIXES_V4.md`。本轮未重新训练模型；原始实验输出仍可能出错，冲突时会明确隔离，不作通过建议。训练使用合成弱监督数据，尚未完成独立人工政策评测。官方来源核对日期仍为 2026-10-21，没有据此宣称资料现行有效。v0.3 的检索与材料环境安装说明见 `docs/WORKFLOW_V3.md`；历史训练实验见 `docs/IMPROVEMENTS_V2.md`，首轮记录见 `docs/IMPLEMENTATION_REPORT.md`。

## 启动

需要 Python 3.10+。核心网页和 TXT 读取使用标准库；文字 PDF 读取需要可选的独立材料环境，配置见 `docs/WORKFLOW_V3.md`。

Windows 双击 `start.cmd`，或在项目目录运行：

```powershell
python launcher.py
```

打开 http://127.0.0.1:8765 。启动器会在发现本次独立训练环境、经校验的基础模型和适配器时，一并启动本地模型；其他电脑缺少这些文件时仍可运行规则版。按 Ctrl+C 停止，启动器会清理自己启动的模型进程。只运行规则版可用 `python app.py --open-browser`；该命令支持 `--port 8767` 更换端口。应用只监听本机，不对局域网公开。

## 可以体验的功能

1. **政策匹配**：选择合成案例或填写情况，点击“开始核对政策”。结果直接显示资料中的金额口径、准备步骤和办理渠道；通过“查看中文报告”预览、打印或下载独立 HTML，也可另导出完整 JSON。缺失信息跨事项合并，可点击定位；在读、已超期分别提示。
2. **知识库**：查看三项可初筛事项与历史资料。首笔和第二笔生活补贴是同一政策的两个环节，不能将卡片金额重复累计。
3. **证据检索**：中文字符／双字词 BM25，支持参考日期和显式包含历史资料。当前不是向量检索，也不声称使用重排模型。
4. **训练与评测**：查看真实训练记录摘要、复制命令、运行 10 个合成场景／30 项结论验收。这里的验收比例只属于规则程序。模型诊断另列完整开发集的结论、结构完全一致率及各类别精确率／召回率。
5. **一致性对照**：模型独立生成后逐项比较结论、决定性引用、缺失字段与准备清单。原始模型输出保留，差异不被规则答案覆盖。修改表单后须重新初筛，才能调用模型或导出。
6. **政策导入**：下载 JSON 模板，人工更新政策字段、条款和规则后导入。新政策／版本使用新的唯一 id；导入会持久化到 `runtime/policies.sqlite3`，不会覆盖现有记录。

7. **材料核验**：读取文字 PDF/TXT，逐项确认字段。缺少毕业日期时可以在材料页直接补齐并重算，无需重新选择文件；逐月明细标明本次计入的连续月份。确认后可留在材料页继续处理下一份文件。
8. **人工复核**：36 条答案留空的合成草稿，人工记录依据后导出。进度自动暂存于当前浏览器标签页，刷新可恢复；通过“备份全部复核进度”和“恢复复核草稿”可长期保存并继续编辑。待复核数据始终不能作为正式标注导出。

网页导入更新的是运行时知识库。训练脚本固定读取 `data/policies.json`，人工审核新资料后应更新这个版本化文件并重新生成数据，不能把导入动作当成模型已经学习了新政策。

## 首批杭州数据

| 事项 | 来源 | 当前规则范围 |
|---|---|---|
| 应届毕业生生活补贴首笔 | 杭州人社 2024-05-13 指南 | 国内普通高校、中国国籍、全日制；含六个月参保、起算时间、重复领取等核验 |
| 应届毕业生生活补贴第二笔 | 同一指南 | 同一覆盖范围；已领首笔、十二个月参保等核验 |
| 应届大学生租房补贴首笔 | 杭州侨联 2026-03-25 官方答复 | 国内学历的一般首笔条件；家庭住房、其他住房优惠、毕业与参保期限 |
| 2017 年高学历生活补贴文件 | 杭州市政府公报 | 历史资料，默认不参与检索与初筛 |

证据正文是人工要点转述，保留原链接和原文章节。更多来源与已知限制见 `docs/SOURCES.md`。境外学历、非全日制、外国国籍等未覆盖情形显示“待核验”，不会直接套用国内全日制规则拒绝申请。

材料功能只在本机读取文件，文字 PDF 使用可选的独立 pypdf 环境；TXT 可直接使用。原始材料不发送给模型。新“人工复核”页提供 36 条无答案合成草稿，当前没有已完成的人工基准。

申请信息不写数据库或日志。政策匹配表单和上传原文件只保留在页面内存，导出报告由浏览器下载。复核工作台的案例及笔记单独暂存于本标签页的 sessionStorage；关闭标签页后不保证保留，请下载草稿备份。准备清单区分原文列明信息与建议核验信息。本应用不收集身份证号码或银行卡号码。

## 接入本地模型

启动支持 `/v1/chat/completions` 的本地模型服务。在项目根目录创建 `.env.local`，参考 `.env.example`：

```dotenv
HCT_LLM_BASE_URL=http://127.0.0.1:11434/v1
HCT_LLM_MODEL=你的实际模型名称
```

重启应用后，在政策结果卡点击“实验模型交叉核验”。模型收到该政策条款和当前表单，返回结构化结果；规则结果保持独立。默认先检索所选事项的相关证据，再补齐已录入条件与清单关联条款。可切换旧版整份条款对照；模型未收到规则结论。网关检查输出结构、政策编号、所给引用和材料编号，但**编号存在并不证明语义支持**，需要独立评测。结构通过后再运行显式规则对照，不能用这一对照声称验证了解释文字。模型原始输出和对照结果包含在导出的当前报告中。连接出错会显示错误，不会用规则答案伪装模型答案。

默认只接受本地地址。确需使用远程 HTTPS 模型服务时，另设 `HCT_ALLOW_REMOTE_LLM=1`；此时所填信息会发送给指定服务，使用合成案例做研究更合适。密钥仅放环境配置，不放网页代码。

## SFT / GRPO 实验

第一阶段训练任务：**给定政策证据与人物条件，输出结论、引用、缺失字段和准备清单**。检索器固定；尚未实现多轮工具调用 GRPO 或自主检索策略训练。

先生成开发用数据，完全不需要 GPU：

```powershell
python -m training.build_dataset
python -m training.train sft --dry-run
python -m training.train grpo --dry-run
```

数据写入 `data/generated/`。默认 240 个人物条件组，生成 720 条政策任务；分为 SFT 与 GRPO 两种格式，不是两倍独立样本。

同时保存 `train_balanced_sft.jsonl` 与 `train_balanced_grpo.jsonl`。当前训练分割含 388 条任务，默认将三类各下采样为 46 条，得到 138 条类别平衡任务。训练入口默认用该平衡版本；验证集与测试集不做平衡抽样。派生格式和下采样都不是额外的独立样本。

如果已在这次开发中创建独立实验环境，可在本项目目录使用 `./run-training.ps1 -Mode sft -DryRun`；脚本会优先复用工作目录中的环境及经校验的本地模型。也可用 `python -m training.train sft --model 本地模型目录` 明确指定模型位置。

- 标签为规则引擎生成的**合成弱监督**，`human_reviewed=false`，不是人工标注。
- 生活补贴文件族用于训练与验证；租房文件族作为独立测试来源，不进入训练。
- 训练和验证按人物组隔离，但使用同一政策来源；测试按文件族隔离。测试推理时仍会提供该文件的证据。
- 文件族非常少，不能据此证明跨城市、跨政策泛化。正式评测需扩大文件数量，人工复核标签，固定测试集与版本。

训练环境建议单独创建，避免影响现有 Python：

```powershell
python -m venv .venv-training
.venv-training\Scripts\Activate.ps1
# 按 PyTorch 官方安装说明先安装匹配 CUDA 的 torch
python -m pip install -r requirements-training.txt
python -m training.train sft --max-steps 1
python -m training.train sft
python -m training.train grpo --max-steps 1
python -m training.train grpo
```

这里给出新环境配置命令，不会自动购买算力。本次已经在工作目录中创建独立 `training-venv` 并安装验证，未改动全局 Python。实际版本见 `docs/training-environment.json` 和 `requirements-training.lock.txt`。其他环境应先确认 PyTorch / CUDA 与驱动兼容。

默认以 Qwen2.5-0.5B-Instruct、LoRA rank 8、短结构化输出开始，见 `training/config.json`。本次平衡训练的 PyTorch 峰值已分配显存约为 SFT 2.88GiB、GRPO 1.28GiB，不含桌面及其他进程占用；其他配置不能直接套用。脚本会在权重上 GPU 前检查样本 token 长度；超预算时停止，避免截断证据却保留依赖该证据的标签。出现超长样本时，应先缩短相关证据并复核标签，或经显存试验后调整长度。

Hugging Face 网络不可达时，可在已安装训练依赖的环境运行 `python -m training.download_model`，从 Qwen 的官方 ModelScope 仓库下载到 `.model-cache/Qwen2.5-0.5B-Instruct`，逐文件校验 SHA-256。然后在训练命令中用 `--model .model-cache/Qwen2.5-0.5B-Instruct` 指定该目录。基础模型权重不在源码压缩包中。

GRPO 必须读取 SFT 产生的 LoRA 目录，默认 `checkpoints/sft`；可通过 `--sft-adapter` 指定。奖励为结论正确性门控下的引用 F1、缺失字段 F1、材料 F1 和格式检查。引用编造、重复编号得零分；格式正确但结论错误只得很低奖励。没有使用独立奖励模型，也没有把 GRPO 等同于完整 RLHF 人类偏好流程。

## 评测自己的模型预测

预测文件每行：

```json
{"case_id":"测试样本中的 case_id","completion":"模型生成的完整 JSON 文本"}
```

```powershell
python -m training.evaluate --gold data/generated/test_grpo.jsonl --predictions my_predictions.jsonl
```

也可用 `python -m training.predict` 加载已训练适配器产生真实预测。使用 `--limit 3` 时，只是前三条样本的流程检查；脚本会同时保存所选 `.gold.jsonl` 和范围元数据，不能将此当成完整测试集结果。

缺失预测计作失败，不只评价成功返回的样本。结论准确率、有效输出率与各字段 F1 会写入 `training-runs/evaluation.json`。同时保存逐类指标、混淆矩阵、按政策统计与 `.details.jsonl` 逐条错误。正式方案见 `docs/EXPERIMENTS.md`。

## v0.2 实验与默认模型

本轮训练数据为 384 条、302 条不同任务，按每个生活补贴事项的三类结论平衡。候选模型使用原有全部 92 条开发任务比较；默认模型按结构完全一致率、结论一致率依次选择，相同则优先 SFT。记录与权重散列冻结在 `checkpoints/selection.json`，一键启动会检查散列。手工重新训练时使用新的输出目录，保留冻结记录。

第二轮 SFT 的 PyTorch 峰值已分配显存为 2.938 GiB，GRPO 为 1.328 GiB；GRPO 20 步中 9 步出现非零梯度与组内奖励差异。这说明训练实际执行，不直接证明效果提升。完整记录及复现命令见 `docs/IMPROVEMENTS_V2.md`。

**本轮训练未改善模型效果，因此默认仍使用原平衡 GRPO。** 全部开发集为 61/92 与弱标签结论一致；冻结后的租房子集为 22/48。当前以显式规则作为可审计初筛，模型结果单独核对。候选模型和失败记录均保留在源码包中。

## v0.3 快速演示

先在“政策匹配”加载合成案例，再进入“材料核验”体验正常参保与参保中断样例。提取字段默认不勾选，需核对并明确确认后才填入表单。材料参考日期变化时重新提取。

“人工复核”初始为 0/36，仅导出用户实际确认的记录。旧模型表格属于固定提示的历史实验；新检索流程只完成联调，没有沿用旧数字声称新准确率。材料环境配置、限制和评测命令见 `docs/WORKFLOW_V3.md`。
