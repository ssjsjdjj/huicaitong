## 使用方法

启动方式不变：双击 `start.cmd` 或执行 `python launcher.py`。已有启动进程需要重启才会载入后端修改。核心应用及 TXT 读取无需新增第三方依赖；文字 PDF 使用原有可选材料环境。

1. 填写情况，或载入合成案例，点击“开始核对政策”。参考日期默认使用浏览器北京时间当天；合成案例保留各自固定日期，来源核对日期仍是原资料日期。
2. 不知道单位或住房口径时，打开旁边的填写指引，暂时保留“待确认”。
3. 材料核验页可直接编辑毕业日期和参考日期。读取过的文件只在内存中保留；修改后保存日期即可重算。提取候选始终默认不勾选，需逐项确认。
4. 点击“查看中文报告”阅读结果，可下载 HTML 或打印。完整结构化实验记录另存 JSON。
5. 复核工作台自动暂存至当前标签页。离开较久或关闭前，先“备份全部复核进度”；重新打开后用“恢复复核草稿”。正式已确认标注继续使用单独的导入/导出入口。

## 数据与安全边界

- 匹配表单和原始材料不写入数据库、日志或浏览器存储。sessionStorage 只保存复核工作台中的案例和笔记；文件读取缓存会在清空资料或换合成案例时清除。
- 草稿恢复只校验并恢复部分填写内容，绝不会把 pending 提升为 reviewed。正式标注验证规则仍要求复核者、时间、完整答案和对应政策快照。
- 金额来自已收录资料中的明确标准与比例，不是获批金额或当前政策承诺；同一生活补贴不重复累计。博士时间例外不推定切分日期或无条件金额。
- 模型仍可能误判。本次修复的是冲突展示及应用使用风险，没有把规则输出当成模型预测，也不声称模型准确率提高。原始输出、检索轨迹和规则对照分别保留。
- 本机图片 OCR 仍受环境限制，不通过绕过系统脚本策略来启用。文字 PDF/TXT 可用；照片或扫描 PDF 可从原系统导出文字版本，或提供完整逐月 TXT。
- 来源现行效力、政策覆盖范围和独立人工基准仍需后续工作。这里的自动化检查属于程序回归，不是政策准确率或 GRPO 收益证明。
